# 原生宠物窗口采用物理坐标与逻辑速度分层模型

宠物的桌面位置必须只有一个事实来源。Rust 领域模型维护原生窗口左上角物理坐标、
窗口物理尺寸、当前显示器、安全边距和碰撞结果；PixiJS 只负责窗口内部的精灵渲染，
不得维护另一套桌面坐标。行为速度使用逻辑点每秒表达，每次位置积分只按当前显示器
的缩放比例转换一次，再把结果写入 Tauri 原生窗口。

macOS 平台适配层负责读取全部显示器的可用区域、缩放比例、主显示器和当前鼠标
位置，并转换成可注入的显示器快照。显示器运行时标识只用于关联同一次运行中的
布局，不写入偏好或诊断；标识不包含分辨率或缩放，同名显示器才按当前排列追加
运行时序号。持久偏好继续保存版本化的物理 `x/y`。启动时只有保存的
窗口矩形完整落在当前某块显示器的安全区域内才恢复，否则召回到鼠标所在显示器
的右下安全角；鼠标不在已知显示器时依次回退到主显示器和第一块可用显示器。

自主运动只在当前显示器安全区域内反弹，不跨屏。用户或系统明确改变原生窗口位置
时，以窗口中心重新判断当前显示器。显示器断开、分辨率、缩放、排列或可用区域
变化后，优先在原显示器内收拢；原显示器消失时选择离旧窗口中心最近的剩余可用
区域。Tauri 的移动／缩放事件负责即时同步，低频布局核对负责覆盖 macOS 未发送
对应窗口事件的显示器生命周期变化。

## Considered Options

- 让前端维护逻辑桌面坐标会与原生窗口、显示器缩放和系统排列形成双重事实来源，
  也无法可靠处理负坐标和显示器断开。
- 统一使用逻辑坐标持久化需要绑定某次显示器缩放；显示器变化后容易发生重复缩放
  或恢复到错误位置。
- 创建全屏透明覆盖层或每块显示器一个宠物窗口会扩大焦点、命中、Space 和全屏
  风险，不符合单一紧凑宠物窗口的产品约束。
- 仅依赖当前显示器不能正确实现鼠标屏召回，也无法处理窗口所在显示器已经断开
  的情况。

## Consequences

所有原生窗口移动入口都必须经过同一 Rust 安全区模型。未来 Issue 04 的拖拽和
Issue 05 的行为调度可以复用外部位置采纳与可控运动 seam，但不能各自新增桌面
坐标状态。行为调度必须保存碰撞后反转的逻辑速度，且不得借运动循环自主切换
显示器；原生位置控制器因此必须把完整运动结果返回给调用方，不能只返回坐标。

修改窗口尺寸、显示器快照算法、缩放转换或持久位置格式时，需要重新覆盖负坐标、
不同缩放、上下排列、断开、可用区域收缩和非法数值测试，并运行真实原生窗口
smoke。双显示器人工环境不可用时，必须如实记录单屏实测，并以确定性 Rust 快照
测试补充边界证据，不能把模拟结果写成双屏人工通过。
