# macOS 桌宠预览候选版规格

Status: accepted

## Context

截至 2026-07-30，仓库已经具备正式 Tauri 2 主线、Rust 宠物包校验、
Vue/PixiJS 预览工作台、macOS 菜单栏恢复、真实桌面 smoke、视觉/E2E、CI 与
架构反馈门禁。当前内置“卷卷”仍是一张工程占位帧，启动形态仍以预览工作台为
中心，尚未形成可日常常驻的真实桌宠体验。

本规格把下一阶段定义为 `macOS 预览候选版`：在实际 Apple Silicon macOS
环境中完成一只正式宠物的核心陪伴循环、产品化窗口形态、恢复控制、常驻性能和
人工 QA。它是单平台体验候选，不改变 `外部 Alpha` 仍需安装、权限、分发和
Windows 验证的边界。

本规格继承以下既有决策：

- `.scratch/oh-my-pets-p0-alpha/issues/01-define-p0-companion-loop.md`
- `.scratch/oh-my-pets-p0-alpha/issues/04-define-pet-pack-boundary.md`
- `.scratch/oh-my-pets-p0-alpha/issues/06-define-first-pet-content.md`
- `docs/adr/0001-tauri-rust-pixijs-desktop-architecture.md`

2026-07-30 的 grilling 已逐项确认窗口、输入、多显示器、状态、美术、投喂、
设置、性能和验收边界，并获得用户最终确认。

## Goals

- 启动后直接得到一只透明、无边框、始终置顶且不抢焦点的“卷卷”，而不是工程
  预览工作台。
- 以一个随宠物移动的小型原生窗口承载日常活动，并在多显示器、Space、全屏、
  锁屏与休眠变化后可靠恢复。
- 完成 15 个语义动作对应的自主行为、点击、拖拽、抛掷和无副作用文件投喂
  循环。
- 交付约 86 帧、具有明确使用权且通过逐帧检查的正式“卷卷”宠物包。
- 用菜单栏承担高频控制和救援，用按需偏好设置承担低频设置与诊断。
- 在真实 Apple Silicon macOS `.app` 中达到已确认的启动、延迟、CPU、内存、
  四小时常驻和人工 QA 门槛。

## Non-goals

- Windows 实现或验收、Intel Mac 兼容承诺，以及未实际验证的 macOS 版本承诺。
- 签名、公证、DMG、正式安装器、自动更新、外部分发或外部测试用户招募。
- 用户侧宠物包导入、宠物商店、多宠物、换装、多配色或第二只宠物。
- 账号、云同步、遥测后端、AI 对话、养成数值、任务、提醒或番茄钟。
- 音效、语音、配乐、口型同步、系统通知或读取前台应用内容。
- 全屏透明覆盖层、逐像素 Alpha 命中或透明区域局部鼠标穿透。
- 解决 macOS 菜单栏拥挤或刘海遮挡状态项的全部系统布局限制。
- 将现有预览工作台继续作为普通用户的默认产品界面。

## Product Shape

### Window topology

- `pet` 是默认可见的透明、无边框、无阴影、始终置顶宠物窗口；启动时不得抢夺
  当前应用焦点。
- `preferences` 是按需打开的普通设置窗口，默认隐藏；关闭设置窗口不退出应用。
- 当前预览工作台只保留为偏好设置“高级”区域中的开发入口，不在正常启动时
  显示，也不参与候选版日常体验验收。
- 菜单栏入口独立于两个窗口存在；宠物隐藏、移出有效显示器或开启鼠标穿透时，
  用户仍能从菜单栏恢复。
- 应用正常启动只显示宠物；退出必须显式使用菜单栏“退出应用”。

### Pet window geometry

- 不创建覆盖整块屏幕的透明窗口。宠物使用能容纳所有动作外廓的稳定小窗口，
  原生窗口随宠物在桌面上的逻辑位置移动。
- Rust 负责行为、物理、安全区域、原生窗口位置和状态持久化；PixiJS 只在固定
  内容画布内渲染语义动作，不通过逐帧 IPC 驱动动画。
- `hitbox` 与 `dropZone` 只决定应用如何解释落在窗口内的输入；候选版不把
  逐像素命中或局部透明区域穿透作为验收条件。
- 尺寸提供小、中、大三级，默认中；缩放不能改变脚底基线、安全区或命中区域
  的语义一致性。

### Multi-display and Spaces

- 同一时刻只有一个宠物实例。自主活动只发生在当前显示器，不自主跨越显示器。
- 用户把宠物拖到另一显示器后，该显示器成为当前显示器。
- 菜单栏“召回宠物”把宠物带到当前鼠标所在显示器的安全角落。
- 显示器断开、分辨率或排列变化时，宠物恢复到最近可用显示器的有效安全区域，
  不得永久留在屏幕外。
- 本阶段不制作跨显示器跳转动画。
- 宠物跟随所有 Space，并在普通全屏应用上保持可见；受系统保护且不允许覆盖的
  表面不作额外承诺。

## Interaction Requirements

### Pointer input and pass-through

- 默认紧凑宠物窗口接受输入；落在 `hitbox` 内的点击触发 `tap_react`。
- 用户可从 `hitbox` 抓起宠物。拖拽时进入 `drag_hold`，释放后继承有限速度，
  经过 `fall -> land -> idle`，碰撞和反弹后始终回到可见安全区域。
- 整窗鼠标穿透是显式会话开关，默认关闭且不跨启动保存。
- 开启穿透后点击、宠物拖拽和系统文件拖放全部不可用；菜单栏必须显示当前状态
  并能关闭穿透。
- 安静模式下仍允许拖动宠物改变位置，但点击和文件投喂不触发趣味反应。

### File feeding

- 接受单个本地普通文件，不按扩展名或大小读取内容。
- 文件路径只能在系统拖放事件处理期间瞬时用于判断文件类型；不得写入设置、
  日志、诊断、错误报告或遥测。
- 不读取或保存文件名、内容、哈希、预览和文件数据，不复制、移动、删除、修改
  或上传用户文件。
- 有效投喂触发 `feed_react`；文件夹、多个文件或非普通文件不算投喂，只触发
  一次短暂 `curious`，不弹错误提示。
- 开启整窗鼠标穿透或安静模式时，不接收文件投喂。

## Behavior Requirements

### Required semantic actions

正式宠物包和行为宿主必须共同支持以下 15 个动作键：

`intro`、`idle`、`walk_left`、`walk_right`、`sleep`、`drag_hold`、`fall`、
`land`、`tap_react`、`feed_react`、`curious`、`edge_play`、`quiet_idle`、
`rare_1`、`rare_2`。

- 每个动作必须存在真实、可测试的触发路径，不能只在清单中声明，也不能统一
  回退到 `idle`。
- 自动测试使用可注入时钟和固定随机源覆盖全部状态与转换；人工 QA 不等待真实
  的 15–30 分钟稀有动作周期。
- 用户主动交互优先于自主动作；拖拽状态不得被定时器、全屏变化或随机动作抢占。
- 普通自主行为保持在当前显示器边缘；低频招牌动作可短暂进入中央，但不得超过
  3 秒，结束后回到安全区域。

### Timing and activity

- 首次启动在 15 秒内完成 `intro` 和轻量引导。
- 非首次启动后 60 秒内至少出现一次明显自主动作。
- “标准”活动频率下，普通趣味动作的目标间隔为 3–8 分钟，稀有动作最多每
  15–30 分钟出现一次。
- “低／标准／高”活动频率跨启动保存，三档必须保持严格的由低到高关系；具体
  参数集中配置并由确定性测试覆盖，不向用户暴露逐动作概率或物理参数。
- 长时间无交互可从 `idle` 进入 `sleep`，新的有效交互恢复到 `idle` 或对应
  直接反馈。

### Quiet, fullscreen and lifecycle

- 安静模式由用户显式开启，只在本次进程会话有效。宠物回到安全角落，只允许
  `quiet_idle` 与 `sleep`；可被拖动重新定位，但不响应点击或投喂。
- 菜单栏必须显示安静模式当前状态。重启应用退出安静模式，并恢复用户保存的
  活动频率。
- 进入全屏应用时自动降频：暂停自主移动、边缘玩法和稀有动作，但保留
  `quiet_idle`、`sleep`、轻量状态变化及用户主动点击、拖拽和投喂。
- 退出全屏后恢复保存的活动频率，不把自动降频写入设置。
- 系统锁屏或休眠时暂停行为计时；恢复后从当前状态继续，不补播错过的动作。
- 不读取应用名称、窗口内容、摄像头、麦克风或会议状态来推断用户场景。

## State and Controls

### Persistence

| 状态                   | 跨启动保存 | 默认或恢复规则                     |
| ---------------------- | ---------- | ---------------------------------- |
| 宠物尺寸               | 是         | 中                                 |
| 活动频率               | 是         | 标准                               |
| 开机启动               | 是         | 关闭                               |
| 最后有效位置           | 是         | 越界时恢复到鼠标所在显示器安全角落 |
| 安静模式               | 否         | 关闭                               |
| 隐藏状态               | 否         | 启动时显示宠物                     |
| 鼠标穿透               | 否         | 关闭                               |
| 当前动作、速度和计时器 | 否         | `idle`，首次启动除外               |

持久化数据损坏或版本不兼容时必须使用安全默认值启动并保留可理解的本地诊断，
不得导致宠物永久不可见或应用无法退出。

### Menu bar

菜单栏只提供高频控制和救援：

- 显示／隐藏宠物
- 开启／退出安静模式，并显示当前状态
- 开启／关闭鼠标穿透，并显示当前状态
- 召回宠物到鼠标所在显示器
- 打开偏好设置
- 退出应用

### Preferences

偏好设置只提供低频设置和诊断：

- 尺寸：小／中／大，默认中
- 活动频率：低／标准／高，默认标准
- 开机启动，默认关闭
- 重新加载内置“卷卷”
- 重新显示新手提示
- 导出本地诊断摘要
- “高级”区域中的开发预览入口

始终置顶是固定产品行为，不提供开关。不增加音量、逐动作开关、概率、物理参数
或复杂排程。

## First-run Experience

- 首次启动不显示模态向导或设置窗口。
- 宠物先播放 `intro`，随后最多显示两条自动消失且不阻塞输入的提示，说明
  “可以点击、拖动或投喂文件”以及“更多控制在菜单栏”。
- 新手提示只自动出现一次；正常重启不重复。用户可从偏好设置重新显示。
- 引导状态损坏时宁可重新显示一次，也不能阻止宠物启动。

## Production Pet Content

- 候选版只向普通用户提供内置“卷卷”；用户宠物包导入延期。宠物包格式、
  校验器和开发／测试加载能力继续保留。
- Codex 负责正式素材交付，可以使用 AI 辅助，但最终资产必须经过人工统一、
  逐帧检查和来源记录。
- 角色保留橘白配色、圆头短腿、粗卷尾、深棕轮廓、青色项圈、安静好奇且偶尔
  笨拙的身份锚点；重新设计为原创、少色块、无渐变的扁平 2D 卡通风格。
- 当前 `atlas.png` 只作工程和构图参考，不直接作为正式资产。
- 正式包覆盖 15 个动作，目标 86 帧，允许 80–96 帧；不能用重复单帧伪造动作
  完成。`rare_1` 与 `rare_2` 的叙事和帧预算优先于非核心循环动作。
- 沿用 `320 x 320` 标准画布、单图集、统一脚底基线、`hitbox`、`dropZone` 与
  `bubbleAnchor`。中号宠物可见高度目标约 128–144 px。
- 图集、预览图、清单和来源说明必须进入正式宠物包；不加入音频、第二视角、
  换装、季节皮肤或额外组件图层。

## Performance and Stability

性能数据在实际验收的 Apple Silicon Mac 上测量，并记录硬件、macOS 版本、
构建类型和测量方法。本阶段只对这些实际环境作出候选版结论。

- 冷启动后 5 秒内显示宠物；首次引导在 15 秒内完成。
- 点击、拖拽与菜单操作从输入到可见反馈不超过 100 ms，且不抢夺当前应用焦点。
- 静置 5 分钟的平均 CPU 不超过 3%；活动动画期间平均 CPU 不超过 15%。
- 常驻内存不超过 250 MiB；连续运行 4 小时后增长不超过 50 MiB。
- 连续运行 4 小时，以及锁屏唤醒、睡眠恢复、Space／全屏切换和显示器变化后，
  不得崩溃、卡死、持续高占用或进入无法由菜单栏召回的状态。
- 性能或资源门槛在合理优化后仍无法达到时，应保留 Rust 状态、行为和平台
  边界，单独评估 ADR 中的渲染器替换退路；不得在本阶段静默降低验收标准。

## Acceptance Criteria

- 八张 v1 closeout 实施票按依赖关系完成；每张票自己的人工 QA 不能被最终整合
  票替代。
- 正常启动只显示正式“卷卷”；偏好设置和开发预览按需出现，宠物始终可从菜单栏
  找回。
- 多显示器、Space、全屏、锁屏、休眠和显示器布局变化均满足窗口与行为规则。
- 15 个动作和所有状态转换通过固定随机源／可控时钟的自动测试。
- 点击、拖拽、抛掷、投喂、安静模式、鼠标穿透恢复和状态持久化在真实 `.app`
  中通过人工验收。
- 正式宠物包通过领域校验、逐帧视觉检查、三档尺寸检查和真实桌面显示检查。
- 启动、延迟、CPU、内存与四小时常驻达到已确认门槛，并保存可复核报告。
- 最后相关改动后执行 `pnpm verify`；桌面改动执行 `pnpm qa:desktop:auto` 和
  交互式 `pnpm qa:desktop`。
- 每票完成 Standards + Spec 双轴 review、中文提交和
  `pnpm closeout:check -- --ticket <path>` 后才能标记 `resolved`。

## Delivery Strategy

- 本专题采用 `docs/agents/branch-management.md` 的临时 integration 模式，
  唯一目标分支为 `integration/macos-preview-candidate`。八张票共同构成一个
  候选版，窗口壳、状态、运动、互动、行为、正式内容、引导与封板之间存在不适合
  单独进入 `main` 的中间态。
- integration 以 `origin/main@6f06cc7` 为事实基线创建，并使用精确匹配的临时
  ruleset；专题整体交付后通过一个最终 Pull Request 合入最新 `main`，随后先
  停用 ruleset，再删除 integration。
- `Issue 01` 与 `Issue 06` 从最新 integration 创建独立 ticket 分支；
  其他票必须等待前置票通过 Pull Request 进入 integration。
- 一张 ticket 只对应一个主要实施分支和一个指向 integration 的主要
  Pull Request。禁止从兄弟 ticket 分支派生或互相合并来绕过 blocking edges。
- 所有 Pull Request 使用 merge commit。ticket Pull Request 必须在最新
  integration 上通过 `macOS ARM64 最终验证`；最终专题 Pull Request 必须在
  最新 `main` 上通过同一 required check。实现 SHA 写入 closeout 后不得
  rebase 或强推。
- 规划资产曾在旧流程下通过 Pull Request #4 提前进入 `main`；随后 Pull
  Request #5 才确立 planning／integration 生命周期。这里不伪造 planning
  bootstrap、不重写 `main`，而是从包含这些历史资产的最新 `main` 创建
  integration，再用独立治理 Pull Request 校正本规格、地图和 tickets。该迁移
  例外由用户于 2026-07-30 明确批准，风险由完整 required check、逐票 closeout
  和最终 integration-to-main review 补偿。
