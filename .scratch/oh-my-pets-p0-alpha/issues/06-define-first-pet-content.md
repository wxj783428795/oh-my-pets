# 定义首发宠物内容与动画清单

Type: grilling
Status: resolved
Blocked by: 01, 04

## Question

首只原创 2D 宠物需要怎样的角色设定、动作集合、状态转换与资源预算，才能完整承载 P0 陪伴循环并验证宠物包规范？请给出可制作、可验收的内容清单，而不是泛化的美术愿景。

## Comments

- 2026-07-28 结合 `Issue 01` 的陪伴循环、`Issue 04` 的宠物包边界以及 `research/social-media-analysis.md` 的传播证据收敛首发内容方向。当前最值得押注的不是复杂功能，而是“3–10 秒能看懂的招牌动作”与一眼可认的宠物轮廓。
- 角色选型优先考虑小窗可读性、拖拽和文件投喂的动作合理性，以及双平台首发的产能风险。相比鸟类、拟人角色或多肢体生物，猫科轮廓最容易在 96–160 px 级别保持可读，也最自然承载“文件投喂”和“边缘玩耍”。
- 因此首发宠物不做多套服装、复杂道具层、口型同步或前后左右完整转面，而是围绕一只原创短腿橘白猫做一套高完成度的固定语义动作。

## Answer

首发宠物定为一只原创短腿橘白猫，暂名「卷卷」。它的内容目标不是“表现设定有多丰富”，而是以最小可制作资源完整承载 P0 的陪伴循环，并验证 [宠物包规范](./04-define-pet-pack-boundary.md)。

1. 角色设定

- 物种与轮廓：短腿、圆头、粗尾巴的橘白猫，主体接近一个圆角三角形，远看能立刻认成“猫蹲着”。
- 性格定位：安静观察、对纸张和文件有强烈好奇、偶尔笨拙、被打扰时会短暂炸毛，但不会长期闹腾。
- 视觉限制：只做一个主视角体系，主要是侧面和轻微 3/4；不做正背面切换，不做复杂透视。
- 色彩限制：橘、奶白、深棕线稿、鼻耳粉、项圈点缀共 5 个主色块，外加 1 层统一阴影；避免渐变和高频纹理。
- 表情集：默认、好奇、困、受惊、得意五种；全部通过眼睛、耳朵、尾巴和身体压缩变化表达，不单独做口型系统。
- 道具预算：只允许 3 个通用道具进入图集。
  - 通用文件纸片
  - 被团成球的纸团
  - 落地扬起的灰尘/速度线

2. 动作清单

这只宠物按“8 组行为 + 15 个技术动作键”制作，既覆盖 P0 体验，也完整覆盖 `Issue 04` 的必填与可选语义动作。

| 动作键 | 行为用途 | 建议帧数 | 循环 | 关键提示点 |
| --- | --- | ---: | --- | --- |
| `intro` | 首次启动入场，落地后看一眼用户 | 8 | 否 | `land` |
| `idle` | 默认待机，含眨眼和轻尾摆 | 6 | 是 | `blink`、`tail-flick` |
| `walk_left` | 向左行走 | 6 | 是 | `step-1`、`step-2` |
| `walk_right` | 向右行走 | 6 | 是 | `step-1`、`step-2` |
| `sleep` | 趴下打盹，轻微呼吸 | 6 | 是 | `settle` |
| `drag_hold` | 被用户拎起后的悬空姿态 | 2 | 是 | 无 |
| `fall` | 松手后下落 | 3 | 是 | `drop` |
| `land` | 落地挤压并回弹 | 4 | 否 | `impact` |
| `tap_react` | 点击后的回头、抖耳或轻炸毛 | 5 | 否 | `react` |
| `feed_react` | 文件投喂时嗅闻、扑住、抱住文件 | 8 | 否 | `sniff`、`grab` |
| `curious` | 鼠标附近探头、抬爪 | 6 | 是 | `sniff` |
| `edge_play` | 在屏幕边缘探头或扒边 | 6 | 是 | `peek` |
| `quiet_idle` | 安静模式下的低动效慢眨眼 | 4 | 是 | `slow-blink` |
| `rare_1` | 招牌动作 A：把文件纸片扑成纸团再得意坐住 | 10 | 否 | `grab`、`crumple` |
| `rare_2` | 招牌动作 B：冲太快滑倒，双爪挂住边缘后偷看用户 | 10 | 否 | `slip`、`catch` |

- 技术动作总帧数目标为 `86` 帧，允许在 `80–96` 帧之间微调，但不再扩展第三个招牌动作。
- `walk_left` 与 `walk_right` 可以共用构图逻辑，但出包时仍必须提供两个动作键，避免在运行时引入额外镜像规则。
- `rare_1` 和 `rare_2` 是这只宠物的核心招牌动作；如果产能吃紧，宁可压缩 `curious` 或 `edge_play` 的帧数，也不要先砍招牌动作。

3. 状态转换与触发策略

- 首次进入：`intro -> idle`。
- 默认挂机：以 `idle` 为主，偶发切到 `walk_left`、`walk_right`、`curious` 或 `edge_play`。
- 长时间无交互或被系统降频时：`idle -> sleep`；被再次激活后回到 `idle`。
- 点击：任意非拖拽状态收到点击后进入 `tap_react`，结束后回 `idle`。
- 拖拽：按下并抓起进入 `drag_hold`；松手后若离地则 `fall -> land -> idle`，若几乎贴地释放则直接 `land -> idle`。
- 文件投喂：拖入文件后进入 `feed_react`；低概率串接到 `rare_1`，否则回 `idle`。
- 招牌动作：`rare_2` 只在活跃状态且接近边缘时触发，避免在屏幕中央上演，保证动作故事清楚。
- 安静模式：只允许 `quiet_idle` 和 `sleep`；禁止 `walk_*`、`edge_play` 与两个 `rare_*`。

4. 资源预算

- 标准画布：`320 x 320`。
- 交付资源：
  - `1` 张图集图片，优先 `.webp`
  - `1` 个 `atlas.json`
  - `1` 个 `pet.json`
  - `1` 张 `preview.png`
- 图集预算：优先控制在 `2048 x 2048` 以内；若裁剪后仍超出，再考虑拆分动作帧密度，而不是扩大格式边界。
- 清单预算：`15` 个动作键、`86` 帧目标、`3` 个通用道具、`5` 个表情层级。
- 可读性预算：中号尺寸下宠物高度以约 `128–144 px` 为主；在最小尺寸下眼睛、耳尖和尾巴动作仍需肉眼可辨。

5. 内容验收标准

- 轮廓验收：在静止截图里，不看标题也能直接认出“这是一只猫”，且不会像狐狸、仓鼠或团子生物。
- 交互验收：点击、拖拽、抛出、文件投喂四类交互各有独立反馈，用户无需文字提示也能分辨。
- 招牌动作验收：`rare_1` 和 `rare_2` 任一动作单独录成 3–10 秒短视频时，旁观者能立刻讲出发生了什么。
- 包规范验收：这只宠物必须完整覆盖 `Issue 04` 的所有必填动作键，并至少使用 `cuePoints` 覆盖行走、落地、投喂和招牌动作四类时刻。
- 产能验收：不引入第二套体型、第二视角、换装、季节皮肤、音效资源或额外组件图层；首发内容必须能在一次美术制作周期内封板。

6. 明确不做的内容

- 不做第二只宠物或同宠物多配色版本。
- 不做语音、配乐、嘴型同步或音频资源交付。
- 不做可穿戴配件、家具、气泡对白、季节主题包或表情贴图库。
- 不做前台应用专属动作，不做读取文件内容后的定制反应。

结论是：首发内容应该是一只原创、轮廓清晰、对纸张有强好奇心的橘白猫，用 `86` 帧左右的高完成度动作覆盖默认陪伴、直接交互和两个可分享的招牌动作。这样既能最低成本验证 P0 的陪伴循环，也能真实检验 `pet.json + atlas.json + 图集` 这条 Rust 宿主内容管线是否足够承载外部 Alpha。
