# 确定外部 Alpha 的发布、权限与恢复策略

Type: grilling
Status: resolved
Blocked by: 03

## Question

怎样让非开发者在 macOS 与 Windows 上安全完成下载、安装、首次授权、升级或卸载，并能从崩溃、黑屏、宠物丢失等常见故障中恢复？请明确签名、公证、安装包、权限引导、日志导出和最低恢复能力的 P0 标准。

## Comments

- 2026-07-28 当前开发环境只有 macOS 14+ Apple Silicon，缺少 Windows 11 实机或可复现的图形验证环境；因此本 ticket 不能把“Windows 外部 Alpha 可发布”当前提，而必须把它视为后续硬门槛。
- 在这个约束下，合理路线只有两种：要么把最近一轮外部试用明确收窄为 macOS 预览版；要么继续保留双平台目标，但把 Windows 安装、权限、恢复和签名链路列为发布前阻塞项，等拿到实机或外部测试者后再放行。
- 为避免与 [ADR-0001](../../../docs/adr/0001-tauri-rust-pixijs-desktop-architecture.md) 的“双平台外部 Alpha”目标冲突，这里明确采用两阶段定义：`预览版` 不等于 `外部 Alpha`；前者只用于当前条件下的受限试用，后者仍以 macOS 14+ Apple Silicon 与 Windows 11 x86_64 双平台验收为目标。

## Answer

发布策略分成两个阶段，而不是把当前的单机条件硬说成双平台已就绪。

1. 阶段划分

- `macOS 预览版`：从 2026-07-28 当前条件出发，先对 macOS 14+ Apple Silicon 做小范围外部试用。它的目标是验证安装、恢复、互动理解和基础稳定性，不代表双平台外部 Alpha。
- `外部 Alpha`：只有在 Windows 11 图形壳、安装器、权限和恢复路径补完实测之后才发布。它仍然遵守现有 ADR 的双平台目标，不降级为“只有 macOS 的正式 Alpha”。

2. 安装包与签名标准

- `macOS 预览版` 与后续 `macOS 外部 Alpha` 都使用官网直接分发的 `.dmg`。
- macOS 安装包必须满足：
  - App bundle 使用 Developer ID 签名
  - Hardened Runtime 开启
  - Apple 公证通过并 stapled 到 DMG
- Windows 不在当前预览阶段分发任何安装包。
- `Windows 外部 Alpha` 的最低标准是带代码签名的安装器，并在至少 2 台干净的 Windows 11 机器上验证安装、首次启动、托盘恢复和卸载流程；在完成这一步前，不生成面对外部用户的 Windows 下载链接。

3. 升级与卸载策略

- `预览版` 和 `外部 Alpha` 都不引入自动更新，统一采用“下载新包后原位覆盖安装”的手动升级策略，减少额外更新链路风险。
- 升级时保留本地状态、宠物包和设置；如果新版本检测到旧状态损坏，可回退到默认宠物与默认窗口位置，但不删除用户导入的合法宠物包。
- macOS 卸载路径明确为：
  - 退出应用
  - 删除 `/Applications/Oh My Pets.app`
  - 如用户希望彻底清理，再删除本地配置与宠物包目录
- Windows 卸载流程只在未来拿到实机后正式锁定；当前不承诺未经验证的“可正常卸载”。

4. 权限与首次引导

- P0 默认不做首次启动权限向导，不在刚安装时连续弹系统授权框。
- 没有权限也必须能完成这些核心行为：
  - 启动宠物
  - 点击与拖拽
  - 文件投喂
  - 菜单栏或托盘恢复
  - 重置位置
- 只有用户主动开启依赖系统能力的功能时，才做一次性定向解释，并明确告诉用户为什么要开、不开会少什么效果、以及系统设置入口在哪。
- 权限被拒绝、撤销或升级后失效时，应用必须降级而不是卡死：保留基础桌宠与菜单入口，关闭受影响的增强能力。

5. 最低恢复能力

无论是 `macOS 预览版` 还是未来 `外部 Alpha`，都必须具备这组最小恢复面：

- 独立于宠物窗口存在的菜单栏或托盘入口。
- 一键 `重置位置`：把宠物拉回当前主显示器的右下安全区域。
- 一键 `关闭点击穿透`：避免用户因误开穿透而“抓不到宠物”。
- 一键 `重新加载宠物`：当前宠物包渲染或状态异常时可回退。
- 一键 `导出诊断包`：无需终端。
- 一键 `恢复默认设置`：保留应用本体可启动，不要求用户手动删配置。
- 崩溃后下一次启动进入安全降级：
  - 默认宠物
  - 中号尺寸
  - 点击穿透关闭
  - 默认角落位置
  - 跳过上次失败的自定义宠物包

达到以下任一情况，就算恢复能力不达标：

- 宠物丢失后只能靠删除配置文件恢复。
- 黑屏或透明窗异常后只能靠终端命令退出。
- 开启点击穿透后，用户无法通过菜单栏或托盘把它关掉。

6. 诊断与日志导出

- 所有运行信息默认只保存在本地，不自动上传。
- `导出诊断包` 至少包含：
  - 应用版本、操作系统版本、设备架构
  - 当前宠物包 `id` 与版本
  - 最近启动次数、崩溃次数、恢复次数
  - 显示器布局摘要、窗口位置、尺寸和关键开关状态
  - 最近错误码与最近若干条本地日志
- 诊断包必须明确排除：
  - 拖入文件的内容
  - 文件完整路径
  - 用户键盘输入内容
  - 前台应用内容

7. 放行门槛

- `macOS 预览版` 的放行门槛：
  - 公证安装包可在干净 macOS 14+ Apple Silicon 机器安装
  - 菜单栏恢复、重置位置、关闭点击穿透、导出诊断包全部可手动验证
  - 已知的 macOS 壳限制已在说明中写明，尤其是“整窗点击穿透与系统级文件拖放不能共存”
- `外部 Alpha` 的放行门槛：
  - `macOS 预览版` 已通过验证闭环
  - Windows 11 实机验证完成
  - Windows 安装、卸载、托盘恢复和签名链路过关

结论是：当前最诚实也最可执行的方案，是先发布一个严格受限的 `macOS 预览版`，同时保留 `外部 Alpha` 的双平台标准不变。这样既不违反已有 ADR，也不会因为缺少 Windows 机器就把未验证能力包装成已可发布能力。
